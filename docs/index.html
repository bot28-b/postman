Welcome, QA Engineer!

Open Postman, import the collection, and start testing immediately. This covers:

  • GET, POST, PUT, PATCH, DELETE
  • Query parameters, filtering & pagination
  • Request headers
  • Bearer token authentication
  • Status code validation (200, 404, 500…)
  • Response body assertions & test scripts
  • Environment variables & Collection Runner

1. Enable GitHub Pages (one-time, repo owner)

  1. Push this repo to GitHub (must be public for the free API)
  2. Go to repo Settings → Pages
  3. Under Build and deployment → Source, select GitHub Actions
  4. Push to main — docs deploy automatically

2. Import into Postman (learners)

  1. Open Postman → Import
  2. Import from GitHub: postman/ folder
  3. Import both files:
    • QA-Learning-API.postman_collection.json
    • QA-Learning-API.postman_environment.json
  4. Select QA Learning API - Live (GitHub) environment (top-right)
  5. Run Health Check (GitHub Pages) → expect 200 OK
  6. Run Get All Users → expect a JSON array

4. Postman Tips

Tests tab

Every request has example tests. After Send, check Test Results:

pm.test('Status is 200', () => pm.response.to.have.status(200));
pm.test('Returns an array', () => pm.expect(pm.response.json()).to.be.an('array'));

Collection Runner

Click the collection → Run → run all folders → see pass/fail for every test.

Environment variables

{{baseUrl}}, {{docsUrl}}, {{httpbinUrl}}, {{token}} — change in one place for all requests.

5. Practice Exercises

  1. Run Health Check and Get All Users — all tests green
  2. POST a new user, then GET by the returned ID
  3. Filter electronics products — assert every item has category: electronics
  4. Call Bearer Token - Valid then Missing (401)
  5. Run all Status Codes requests — assert each code matches
  6. Run Response Delay — assert response time > 2000ms
  7. Run the full Collection Runner — aim for 100% pass
  8. Write your own test on Get All Products — check every product has price
